۱. معرفی پروژه

PyLex Studio یک ویرایشگر دسکتاپ سبک برای زبان پایتون است. کاربر می‌تواند کد بنویسد، فایل باز و ذخیره کند، برنامه را اجرا کند و دو مرحله تحلیل لغوی و نحوی را به صورت مستقل ببیند.

۲. اهداف و نیازمندی‌ها

  • شناخت کلمات کلیدی پایتون مانند if، for، def، class و return
  • تبدیل متن به توکن و بررسی دستور زبان
  • ویرایش فایل، فونت، بزرگ‌نمایی و تم
  • اجرای کد و نمایش خروجی و خطا
  • ساختار ماژولار و تست‌پذیر

۴. تحلیل لغوی (Lexical Analysis)

تحلیل لغوی نخستین مرحله تحلیل برنامه است. در این مرحله رشته کاراکترها به واحدهای معنادار به نام Token تبدیل می‌شود. برای مثال در total = price + 5، شناسه‌ها، عملگر انتساب، عملگر جمع و عدد توکن‌های جداگانه‌اند.

تابع lexical_analysis(source) در ماژول analyzer.py از کتابخانه استاندارد tokenize استفاده می‌کند. هر توکن دارای نوع، مقدار، شماره خط و ستون شروع و پایان است. کلمات رزروشده با نوع KEYWORD مشخص می‌شوند.

from pylex.analyzer import lexical_analysis
tokens = lexical_analysis("if score >= 10:\\n    print('Pass')")
for token in tokens:
    print(token.token_type, token.value, token.line, token.column)

دسته‌های متداول عبارت‌اند از KEYWORD، NAME، NUMBER، STRING، OP، INDENT و NEWLINE. خروجی در تب مستقل تحلیل لغوی نشان داده می‌شود.

۵. تحلیل نحوی (Syntax Analysis)

تحلیل نحوی بررسی می‌کند که توکن‌ها مطابق دستور زبان پایتون کنار هم قرار گرفته باشند. عبارت if True print("x") معتبر نیست، چون بعد از شرط دونقطه لازم است.

تابع syntax_analysis(source) از ast.parse استفاده می‌کند. در صورت موفقیت درخت AST ساخته می‌شود و تعداد گره‌های آن گزارش می‌شود؛ در صورت شکست، پیام SyntaxError و شماره خط و ستون ارائه می‌شود.

from pylex.analyzer import syntax_analysis
result = syntax_analysis("x = 10\\nprint(x)")
print(result.success, result.message)

تفاوت دو مرحله: تحلیل لغوی می‌پرسد «این قطعه متن چه توکنی است؟»؛ تحلیل نحوی می‌پرسد «آیا این توکن‌ها ساختار معتبر پایتون می‌سازند؟»

۶. امکانات ویرایشگر

  • رنگ‌بندی مبتنی بر Pygments برای کلمات کلیدی، Built-inها، رشته‌ها، اعداد، کامنت‌ها، نام توابع و کلاس‌ها

  • میانبر Ctrl+N، Ctrl+O، Ctrl+S، F5 و F6 برای Analyze All

۷. اجرای برنامه

ماژول runner متن برنامه را در فایل موقت می‌نویسد و با مفسر انتخاب‌شده برای Workspace در یک پردازه فرزند اجرا می‌کند. خروجی استاندارد، خطای استاندارد و کد خروج در تب خروجی نمایش داده می‌شوند. زمان اجرا به صورت پیش‌فرض ۱۰ ثانیه محدود است. اجرای پردازه جداگانه مانع بسیاری از اختلال‌ها در پنجره اصلی می‌شود، اما به معنی ایزوله‌سازی امنیتی نیست.

۸. مدیریت Python Interpreter و Virtual Environment

از نسخه 1.4.0 شناسایی و انتخاب مفسرهای نصب‌شده فراهم شده است. PyLex هر مسیر را با اجرای همان فایل اجرایی و دریافت اطلاعات نسخه، پیاده‌سازی، معماری، مسیر prefix و وضعیت محیط مجازی اعتبارسنجی می‌کند. تشخیص محیط مجازی بر اساس تفاوت sys.prefix و sys.base_prefix است و به متغیر محیطی VIRTUAL_ENV وابسته نیست.

  • کشف مفسر جاری و مسیرهای رایج PATH؛ در Windows همچنین استفاده از Python Launcher
  • انتخاب مفسر به صورت Global یا مختص Workspace
  • اولویت انتخاب پروژه، سپس شناسایی خودکار .venv، venv و env و در نهایت مفسر عمومی
  • ساخت محیط مجازی پروژه در پوشه .venv بدون حذف یا بازنویسی محتوای موجود
  • اجرای برنامه، دیباگر و اسکن وابستگی‌ها با همان مفسر انتخاب‌شده
  • اجرای pip از طریق python -m pip برای جلوگیری از نصب در مفسر اشتباه
  • نمایش وضعیت pip و امکان تعمیر یا نصب آن با ensurepip

PyLex برای اجرای برنامه نیازی به فعال‌سازی shell محیط مجازی ندارد؛ مسیر مستقیم executable انتخاب‌شده به پردازه اجرا داده می‌شود. محیط مجازی قابل انتقال مطمئن بین سیستم‌ها نیست و نباید در Git ثبت شود؛ آن را با requirements.txt روی سیستم مقصد دوباره بسازید.

۹. نصب و راه‌اندازی

نیازمندی‌ها: Python 3.10 یا جدیدتر، Tkinter و Git. برای رنگ‌بندی نحوی، نصب وابستگی Pygments از فایل requirements.txt لازم است.

git clone https://github.com/Amirh-Darvishi/pylex-studio.git
cd pylex-studio
python -m venv .venv

# Windows PowerShell
.venv\\Scripts\\Activate.ps1

# Linux / macOS
source .venv/bin/activate

python -m pip install -r requirements.txt
python main.py

چرا venv به جای Docker؟

این برنامه دسکتاپ و دارای پنجره گرافیکی است. اجرای GUI در Docker به تنظیمات نمایشگر X11 یا Wayland و دسترسی‌های سیستم‌عامل نیاز دارد. venv نصب ساده‌تر و تجربه مناسب‌تری برای کاربران GitHub فراهم می‌کند. Pygments تنها وابستگی خارجی برنامه است و با requirements.txt نصب می‌شود.

۹. آزمون‌ها و کنترل کیفیت

مجموعه آزمون‌های واحد، تحلیل لغوی و نحوی، اجرای کد، مدیریت Workspace، شناسایی فایل، ترجیحات کاربر، کشف مفسرها، ساخت محیط مجازی و هدایت اجرا به مفسر انتخاب‌شده را بررسی می‌کند.

python -m unittest discover -s tests -v

فایل GitHub Actions آزمون‌ها را در هر push و pull request اجرا می‌کند. این روند CI به شناسایی سریع خطاهای ناشی از تغییر کد کمک می‌کند.

۱۰. گزارش خطاها و ناوبری

از نسخه 1.1.1 یک پنل Errors در دسترس است که نوع دقیق استثنا مانند SyntaxError و IndentationError، شماره خط، ستون و پیام خطا را نمایش می‌دهد. ستون‌ها در منطق داخلی ویرایشگر صفرمبنا هستند؛ در رابط کاربری شماره ستون به شکل یک‌مبنا نمایش داده می‌شود.

در صورت گزارش یک خطای یکسان از tokenize و ast، گزارش تکراری حذف می‌شود. انتخاب یا دوبار کلیک روی یک خطا، مکان‌نما را به محل خطا منتقل می‌کند و خط مربوطه را برجسته می‌سازد. با ویرایش کد، گزارش‌های قدیمی نامعتبر می‌شوند و باید تحلیل دوباره اجرا شود.

برای اجرای تحلیل کامل از Analyze All یا کلید F6 استفاده کنید. برای پاک‌کردن خروجی‌ها از Clear Results استفاده کنید.

۱۱. امنیت و محدودیت‌ها

  • کد با سطح دسترسی کاربر فعلی سیستم اجرا می‌شود.
  • مهلت زمانی از اجرای بی‌نهایت جلوگیری می‌کند، اما دسترسی فایل، شبکه یا پردازنده را کامل محدود نمی‌کند.
  • کدهای ناشناس را اجرا نکنید.
  • برای اجرای امن واقعی باید sandbox مبتنی بر سیستم‌عامل، کاربر محدود، محدودیت منابع و قطع شبکه طراحی شود.

۱۲. نقشه راه توسعه آینده

  • تب‌های واقعی چندفایلی و ذخیره وضعیت هر سند
  • جست‌وجو و جایگزینی و پرش به خط
  • هایلایت کاملاً مبتنی بر tokenize
  • تکمیل خودکار و راهنمای توابع
  • تحلیل معنایی مانند متغیرهای تعریف‌نشده
  • پشتیبانی از Language Server Protocol
  • ذخیره تنظیمات کاربر
  • بسته اجرایی Windows و Linux
